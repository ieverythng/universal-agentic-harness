## Standing availability; finite missions

The human uses GRILL as the sole cross-branch coordination/decision boundary.
GRILL dispatches bounded contracts to branch parents; each parent owns its local
Team, board, child cleanup, evidence integration and consolidated result. DEV
and RESEARCH, including descendants, do not communicate or delegate directly
across branches. A separately authorized DEV1/DEV2 handoff is narrow, not a
routing/review/scope exception for everyone else.

Availability for future approved missions is distinct from each finite work
budget. No per-task receiver rearm, lease, watcher, new message bus, idle model
heartbeat or endlessly continuing Goal is part of this proved path. A timeout,
revocation, changed binding or unavailable effective Tool returns a concrete
recovery decision; no unsupported cold-recovery success is inferred.

Default to **steer in both directions**, for mission dispatch and ACK/result
replies: it reaches the recipient's next safe step, not mid-Tool preemption.
Use queue only for an explicit request or stated reason. Do not resend already
accepted queued items merely to change delivery mode.

A queued message still needs its normal next-turn claim; a steer message needs
its normal step boundary. Passive wait neither consumes entries nor proves the
peer processed work. It must match native peer source plus nonce and clean up
on abort, timeout and disposal. `whenIdle`, Team waiting and inactive membership
are not unrelated-root completion detectors.

Canonical Tool cancellation can occur **after acceptance or recipient execution**.
`ABORTED` remains an error with no success value, and the delivery receipt can
be lost. The repaired SEND-only finalizer warns **delivery unknown; do not retry
blindly** without inventing a message ID or proving non-delivery. Known
before-dispatch cancellation remains distinct. Correlate existing authorized peer
evidence before any approved recovery; do not repeat effects blindly.
