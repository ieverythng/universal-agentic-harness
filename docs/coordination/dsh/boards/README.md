# DSH ownerboards

One board per existing role parent. These are coordination records, not runtime
registration, work authorization, effect evidence or release qualification.

- [GRILL](<grill.md>) — coordinator and integration decisions.
- [RESEARCH](<research.md>) — bounded source investigation and proposals.
- [DEV1](<dev1.md>) — implementation only under a separately assigned scope.
- [PTC](<ptc.md>) — human-named session; the name does not select a preset or duty.
- [CREATOR](<creator.md>) — explicitly scoped control/plugin qualification.
- [VISUALS](<visuals.md>) — explicitly scoped presentation/visual qualification.

Initial pending scaffolds are created by GRILL at the human's request. Actual
parents must confirm ownership through the reviewed native channel before a
board says enrolled; each then writes its own result. Concrete session IDs and
model/preset/permission fingerprints stay in the private owner-approved registry.
Use steer by default in both directions. File writes do not wake a parent.

through that freeze or create another canonical copy in the dirty checkout.
After the human confirms cutover, parents use the agreed persistent coordination
base. No old mission is resumed by board creation or directory relocation.
