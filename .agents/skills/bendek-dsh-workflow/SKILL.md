# DSH coordination adapter

Apply `/bendek-multi-session-workflow` as the single policy authority. This adapter maps its capabilities; it is not a second coordinator or transport. Use it only for an authorized, nontrivial multi-session mission.

1. **Preflight the live binding.** Check that `session_list`, `session_preflight`, `session_send_message`, and `session_wait_for_message` and the required local native Team/taskboard controls are available. Use `session_list` and preflight the exact visible configured hub and requested parent identities, including the caller; verify the owner-approved direct hub↔parent edges, live status, permissions and exact relevant configuration. Selected metadata can be partial and is not serving attestation; unknown is not permission. Cross-parent fanout requires the caller to be the exact configured hub; a non-hub reports or routes upward to its configured hub, never self-elevates from a thread title or role label. A spoke must not enumerate or contact another spoke. Missing or uncertain binding, role, authority, configuration or capability: stop for owner bootstrap or decision, not arbitrary session discovery, root creation, settings changes or installation.
2. **Route and allocate.** GRILL sends directly to existing configured parents; each parent owns its own flat native Team and task board. Check local `list_agents`, `spawn_teammate`, `send_message`, `wait_agent` and Team task controls, capacity, existing work and dependencies before use. Roster labels and inactive status do not establish serving identity or completion. Use list/get/claim with the current task revision, order dependencies and require explicit completion; write scopes are advisory, not locks. Ordinary subagents are only an explicitly justified fallback, never represented as configured sessions or Teams.
3. **Dispatch and reconcile.** Send each parent the policy's finite correlated mission with exact scope, ownership, dependencies, evidence, budget and stop condition using `session_send_message` to its verified identity. Preserve the default steer and safe-step semantics; queue only when explicitly requested. An accepted receipt is inbox acceptance, not an ACK, result or effect. A canonical post-dispatch `ABORTED` can lose the receipt even if delivery occurred: delivery is unknown; reconcile through an authorized channel or stop, never blindly retry.
4. **Observe and finish.** `session_wait_for_message` passively observes the caller's current inbox with a peer and literal marker; it does not send, resume, search history, consume messages or establish completion. Inspect attributed content for the explicit correlated ACK and terminal result; timeout or absent receipt remains unknown, not failure or success. Use bounded event-driven waiting, not polling. Each parent collects owned jobs and explicit teammate/task outcomes; preserve in-flight work, avoid unsafe cancellation and report partials, evidence and limits. Do not create Goals, impersonate the owner, schedule work or change settings without human authority.

**Bounded skill iteration:** Run a bounded SkillOpt-style iteration (baseline -> mutate -> holdout gate -> accept/reject log) before finalizing major wording changes. Follow the iteration limits and acceptance rules owned by `/bendek-multi-session-workflow`; this adapter does not redefine them.
